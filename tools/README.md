# Вспомогательные скрипты

Одноразовый инструментарий вокруг проекта: не часть приложения, в пакет
`portfolio` не входит, импортируется только `portfolio.adapters` (разбор HTML и
форматов), чтобы не завести вторую реализацию декодирования отчётов.

Запускаются без установки пакета — скрипты сами добавляют `src/` в путь:

```bash
python tools/report_structure.py dump отчёт.html
python tools/anonymize_report.py отчёт.html -o tests/fixtures/report_01.html
```

| Файл | Что делает |
|---|---|
| `_report_grid.py` | общая часть: разбор отчёта в сетку ячеек с разворачиванием `colspan`/`rowspan`, привязка строк к секциям и шапкам |
| `report_structure.py` | инвентарь структуры одного отчёта и сравнение нескольких — инструмент шага 0 |
| `anonymize_report.py` | обезличивание отчётов для `tests/fixtures/` |
| `fix_encoding.py` | починка отчётов с испорченной кодировкой |

Тесты: `tests/test_tools_structure.py`, `tests/test_tools_anonymize.py`,
`tests/test_tools_fix_encoding.py`, `tests/test_encoding.py`.
Фикстура с выдуманными персональными данными — `tests/fixtures/tools/broker_raw_sample.html`.

## `report_structure.py` — инвентарь и сравнение

```bash
python tools/report_structure.py dump отчёт.html          # что внутри одного отчёта
python tools/report_structure.py parse отчёт.html         # что парсер из него вычитал
python tools/report_structure.py compare архив/*.html     # чего нет в каком отчёте
python tools/report_structure.py compare архив/*.html --json > inventory.json
```

`dump` печатает: размер сетки, период, признак обезличенности, число знаков после
точки в числах, список секций с их шапками и опознанными колонками, а также
словари значений: `Тип операции`, `Вид сделки`, `Место совершения сделки`, валюты.

`parse` отвечает на другой вопрос. `dump` показывает **форму документа** — какие
разделы, какие колонки, какие значения у брокера в словаре. `parse` показывает
**результат разбора**: во что превратились строки отчёта.

```
операции: 14
  дата        тип             бумага        количество        сумма  влт
  2024-03-05  BUY             Сбер ао               20     -6000.00  RUB
  2024-03-05  FEE·BROKER      Сбер ао                —        -6.00  RUB
  ...

итоги по типам операций
  тип               событий   сумма денег  влт
  BUY                     2     -12000.00  RUB
  ...
  движение денег за период     -2087.60    RUB

с чем сравнить расхождение денег
  сумма НКД по сделкам      25.00   A-07: входит ли НКД в «Сумму сделки»
  сумма налога            -130.00   A-04: купон брутто или нетто
  сумма комиссий           -17.60   A-06: все ли виды учтены
```

Это рабочий инструмент бэкфилла (T11). При расхождении сверки вопрос всегда
один: куда делись деньги — и отвечает на него разбивка по типам, а не форма
документа. Три подсказки внизу соответствуют трём допущениям, которые закрываются
только реальными суммами: если расхождение совпало с одной из этих сумм, это не
совпадение, а ответ.

Комиссии печатаются по видам (`FEE·BROKER`, `FEE·EXCHANGE`, `FEE·STAMP`,
`FEE·DEPOSITARY`): одной строкой `FEE` неучтённый вид комиссии не разобрать.

Как и `dump`, вывод содержит ваши суммы и названия бумаг — наружу его отдавать
нельзя. Для этого есть `digest`.

`compare` сводит инвентари нескольких файлов:

```
--- operation_type: всего 7
  = Ввод ДС
  = Вывод ДС
  + Дробление   [report_2022-04.html]
  различий: 1 из 7 — именно они и требуют работы
```

`=` — есть во всех файлах, `+` — только в части. Строки с `+` и есть ответ на
вопрос шага 0 «какие типы операций встречаются за всю историю»: парсер, написанный
по последнему месяцу, встретит их на середине бэкфилла, и это будет дороже.

Отдельный блок — **тип операции по секциям**:

```
+ 8.1.1 Зачислено/списано ДС по неторговым операциям :: Погашение облигации
+ 8.2 Неторговые операции с ЦБ :: Погашение облигации
```

Разбивка по секциям здесь принципиальна: одно и то же слово в денежной и в
бумажной секции означает разные события журнала — выплату и списание бумаги.
Общий список без разбивки их путает.

## `fix_encoding.py` — починка кодировки

```bash
python tools/fix_encoding.py архив/ -r --dry-run   # что будет сделано
python tools/fix_encoding.py архив/ -r             # рядом: отчёт.fixed.html
python tools/fix_encoding.py отчёт.html --in-place # поверх, с копией .bak
```

Чинится классическая порча round-trip: текст был в UTF-8, кто-то прочитал его
как CP1251 (или latin-1, koi8-r) и сохранил обратно в UTF-8. «Состояние
денежных средств» превращается в `РЎРѕСЃС‚РѕСЏРЅРёРµ РґРµРЅРµР¶РЅС‹С…`.

Такая порча **обратима точно**: обратное преобразование возвращает исходный
текст символ в символ, и тест это проверяет. Здоровые файлы не трогаются — и это
не эвристика: кодировщик отвергает кириллицу вне своей однобайтной таблицы,
поэтому правильный русский текст в принципе не может быть «улучшен». Круг
принимается, только если доля посторонних символов строго уменьшилась; при
двойной порче кругов будет два.

Чего скрипт не делает: не чинит порчу **с потерей**. Если при первом неверном
чтении часть байтов была заменена на `?` или `U+FFFD`, восстанавливать нечего —
такой файл называется в выводе, код возврата ненулевой, исходник нужно достать
заново.

Починенный файл сохраняется в UTF-8, и объявление кодировки приводится к UTF-8:
иначе следующий читатель повторит ту же ошибку.

### Почему ломается не весь архив

Байт `0x98` в CP1251 не определён, а в UTF-8 он появляется у заглавной «И»
(U+0418). В отчёте со словом «Итого» неверное чтение падает с ошибкой и файл
спасается случайно; ломаются молча ровно те отчёты, где заглавной «И» не
оказалось. Поэтому порча выглядит выборочной — два файла из сотни.

### `digest` — форма архива, которую можно отдать наружу

```bash
python tools/report_structure.py digest архив/ -r -o digest.json
```

`dump` и `compare` печатают отчёт как есть — вместе с названиями бумаг и
комментариями, то есть с вашими данными. Отдавать такой вывод нельзя.

`digest` собирает то же знание о форме, но без значений:

| Что попадает | Чего не попадает |
|---|---|
| подписи секций, заголовки колонок, опознанные логические колонки | названия бумаг, эмитенты, ISIN, номера гос. регистрации |
| словарь **брокера**: типы операций, виды сделок, площадки, валюты | суммы, количества, цены |
| формы чисел и дат (`0 000.00`, `00.00.0000`) | точные даты — период огрубляется до месяца |
| шаблоны комментариев: `Погашение купона № <бумага>` | ФИО, номера счёта и договора, имена файлов с цифрами |
| количества строк по секциям | |

Защита двойная: значения берутся только из строк таблицы (подписи и хвост
документа в словарь не попадают), а затем всё, похожее на ФИО, отбрасывается.
Проверяется тестом на фикстуре с выдуманными персональными данными: ни одна из
них не доезжает до выжимки.

## `anonymize_report.py` — обезличивание

Golden-тесты парсера требуют настоящих отчётов (спека 5.5), а настоящий отчёт —
это персональные данные. Скрипт убирает личное, сохраняя всё, от чего зависит
разбор: структуру, подписи секций, заголовки колонок, названия типов операций,
форму чисел и дат, количество строк.

```bash
# обычный случай: весь архив целиком, с подкаталогами по годам
python tools/anonymize_report.py архив/ -r --out-dir tests/fixtures/

# отдельные файлы или маска — тоже можно
python tools/anonymize_report.py архив/*.html --out-dir tests/fixtures/

# посмотреть, что будет сделано, ничего не записывая
python tools/anonymize_report.py отчёт.html --dry-run

# оставить 0.7 строк операций: архив за годы в фикстуру целиком не нужен
python tools/anonymize_report.py архив/*.html --out-dir tests/fixtures/ --sample 0.7

# воспроизвести «как было в примере»: всё личное одной строкой XXX, даты обнулены
python tools/anonymize_report.py отчёт.html --flat-identity --dates mask
```

### Что подаётся на вход

Аргументом может быть файл или каталог, их можно смешивать. Для каталога:

| | |
|---|---|
| `-r`, `--recursive` | заходить во вложенные каталоги. Структура сохраняется в результате: `архив/2024/отчёт.html` → `фикстуры/2024/отчёт.anon.html` |
| `--pattern` | маска имён, например `'report_2024*'`. Без неё берутся файлы с расширениями `.html`, `.htm`, `.xls` |

Про `.xls`: брокеры отдают ту же HTML-таблицу и под этим расширением — это не
бинарный Excel, и разбирается он так же.

Пропускаются автоматически:

* файлы `*.anon.html` — результат предыдущего прогона. Поэтому результат можно
  складывать рядом с исходниками и запускать скрипт повторно;
* файлы без таблиц — в каталоге архива обычно лежат ещё pdf, скриншоты и
  случайные выгрузки. О каждом таком файле печатается строка: молча превратить
  его в «обезличенный отчёт» хуже, чем пропустить.

Весь прогон идёт с одним файлом соответствий, поэтому бумага получает один и тот
же псевдоним во всех месяцах архива. В конце печатается итог: сколько обработано,
пропущено и не получилось.

### Что с чем делается

| Что | По умолчанию |
|---|---|
| ФИО, договор, счёт, телефон, почта, брокер, сотрудники, депозитарий | псевдоним по категории: `КЛИЕНТ`, `ДОГОВОР-01`, `СЧЕТ-01`, `ДЕПОЗИТАРИЙ-01` |
| суммы, цены, количества | форма без величины: `0 000.00`, `0 000.0000`, `00` |
| даты и время | сдвиг на скрытое число дней, кратное семи; время → `00:00:00` |
| номера сделок | цифры → нули: `B-000000-000000` |
| бумаги: краткое имя, эмитент, ISIN, номер гос. регистрации | стабильный псевдоним: `БУМАГА-01`, `ЭМИТЕНТ-01`, `RU000Z000011`, `РЕГНОМЕР-01` |
| `x:num`, `x:str` — числа Excel в атрибутах | очищаются |
| `<img src>` — логотипы, факсимиле подписей, штампы | удаляются, сама картинка остаётся |
| метаданные документа (автор, компания), `<title>` | удаляются |
| подписи секций, заголовки колонок, типы операций, площадки, валюты | **не меняются** |

### Три решения, которые стоит понимать

**Даты сдвигаются, а не обнуляются.** Обнулённые даты превращают отчёт в
структурный макет: сверка остатков **на дату** по такому файлу не проверяется, а
она и есть смысл golden-теста. Сдвиг сохраняет интервалы, порядок и связь T+1;
кратность семи сохраняет дни недели, то есть торговый день остаётся торговым.
Сдвиг отрицательный — даты в фикстуре из будущего читались бы как ошибка.
`--dates mask` возвращает обнуление, `--dates keep` оставляет как есть.

**Суммы обнуляются.** Сохранить их — значит выложить свои деньги в git. Отсюда
деление: обезличенные фикстуры проверяют **разбор** (секции, колонки, типы
операций, пустой список нераспознанного), а арифметика остатков проверяется на
необезличенном архиве локально, в каталоге вне git. Для таких локальных фикстур
есть `--amounts keep`.

**Бумаги псевдонимизируются по умолчанию.** Состав портфеля — это информация о
вас, а парсеру нужна не она, а форма: ISIN остаётся ISIN-ом (та же форма, иначе
`mapping_v1` его не опознает), эмитент остаётся в кавычках после «ПАО».
Перекрёстные ссылки сохраняются: одна бумага получает один псевдоним и в
портфеле, и в шапке группы сделок, и в комментарии к купону. `--keep-instruments`
оставляет настоящие названия.

### Прореживание: `--sample 0.7`

Отчёт за активный месяц — сотни строк, и парсер проверяется первыми же
десятками. `--sample ДОЛЯ` оставляет заданную часть строк операций, сохраняя
разнообразие и структуру.

Правило применяется к секциям 2, 5 и 8 (`--sample-sections` меняет список) и
только там, где элементов больше двух — на одном-двух прореживание уничтожило бы
секцию:

| Секция | Что прореживается |
|---|---|
| `2. Состояние портфеля ценных бумаг` | строки таблицы |
| `5. Сделки…` (каждый подраздел) | сначала бумаги: выпуск уходит целиком — подзаголовок, его сделки и его «Итого по выпуску»; затем строки внутри каждого оставшегося выпуска |
| `8. Неторговые операции` (каждый подраздел) | строки таблицы |

Не трогаются: подписи секций, шапки, строки «Итого» и «Общий итог», разложение
денежного остатка (секция 1), оценка активов (секция 4), подписи и дата
формирования в конце документа.

Сколько остаётся: доля от числа элементов, округление к ближайшему, но не меньше
одного. `0.7` от пяти — четыре, от четырёх — три, от трёх — две.

Выбор псевдослучайный с зерном от содержимого файла: повторный прогон даёт ту же
выборку, разные отчёты — разную. Значит фикстуру можно пересоздать, и
golden-тест на ней не станет плавающим.

**После прореживания арифметика не сходится**: итоги и остатки считались по всем
строкам. Это осознанная плата — прореженная фикстура проверяет разбор, а не
сверку. Вместе с `--amounts keep` скрипт предупреждает отдельно: настоящие
суммы, не сходящиеся с итогами, вводят в заблуждение сильнее, чем нули.

### Файл соответствий

`--mapping` (по умолчанию `.anonymize-mapping.json` рядом с результатом) хранит
«оригинал → псевдоним» и сдвиг дат. Он нужен, чтобы месяцы архива обезличились
согласованно: одна бумага — один псевдоним во всех файлах, иначе сквозной импорт
архива распадётся на несвязанные позиции.

**Этот файл — ключ к деобезличиванию.** Он в `.gitignore`; хранить его следует
там же, где исходные отчёты, то есть вне репозитория.

### Кодировка

Оба скрипта определяют кодировку **по качеству результата, а не по объявлению**.
Файл, сохранённый в UTF-8 со старой метой `charset=windows-1251`, читается как
CP1251 без единой ошибки — CP1251 определён почти на всех байтах, — и русский
текст молча превращается в `РЎРѕСЃС‚РѕСЏРЅРёРµ РґРµРЅРµР¶РЅС‹С…`.

Результат обезличивания **всегда объявляет UTF-8** через `<meta charset="utf-8">`.
Это не косметика: libxml2 при выводе выбрасывает `<meta http-equiv="Content-Type">`
и оставляет только HTML5-форму. Отчёты, где объявление было лишь в старой форме,
теряли его совсем — байты корректные, а браузер, открывая файл локально, угадывал
кодировку по локали и показывал `РЎРѕСЃС‚РѕСЏРЅРёРµ` при исправном файле.

`report_structure.py dump` показывает выбранную и объявленную кодировку, а
обезличивание предупреждает в двух случаях:

* объявление не совпадает с содержимым — сам файл при этом читается правильно;
* даже лучший вариант выглядит мусором: файл был испорчен **до** обезличивания.
  Скрипт его не чинит и байты не трогает — чинить вслепую значит наложить второй
  слой перекодировки на первый. Исходник нужно достать заново.

### Результат нужно просматривать глазами

Скрипт печатает раздел «остаточные подозрения»: кавычки с неопознанным
названием, ISIN или номер регистрации вне распознанных колонок, похожее на ФИО,
похожее на адрес почты. Собственные псевдонимы скрипта в этот список не
попадают — в том числе псевдо-ISIN иностранных бумаг вида `US000Z000288`, где
код страны сохранён от оригинала. Это не гарантия — свободный текст обезличивается
эвристиками, и брокер может написать в комментарии что угодно:
«зачисление по поручению Иванова И. И.» скрипт поймает, а
«перевод по заявлению от 12-го» — нет.

Поэтому порядок такой:

1. `--dry-run` и посмотреть отчёт о заменах;
2. прогон, затем `git diff` или просмотр результата;
3. только после этого коммит фикстуры.

### Проверка формы

После обезличивания скрипт сам сравнивает структуру входа и результата той же
стадией 1 парсера (`extract_tables`): число таблиц, строк и ячеек в каждой строке.
Если что-то разошлось — файл не записывается и печатается причина. Фикстура,
у которой поехала форма, проверяла бы не то, что в отчёте.
