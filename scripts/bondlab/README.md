# bondlab — одноразовый трек по облигациям

Выгрузка справочных данных с MOEX ISS и сверка собственных доходностей с
биржевыми. Реализация `docs/PARALLEL-TRACK.md`, треки A и B1.

**Код здесь одноразовый.** Он будет выброшен, когда дойдёт дело до боевого
`adapters/moex.py` этапа 2. Переживут переписывание три вещи, и внимание
тратится на них: сохранённые ответы ISS, тесты с эталонными числами, записи в
`ASSUMPTIONS.md`.

Расчётное ядро — постоянное: `src/portfolio/calc/bonds.py`, слой `calc/` со
строгим mypy. Этот каталог его только кормит данными.

## Красные линии

Прямо из документа трека. Нарушение любой означает выход за периметр:

* **никакой фильтрации выгруженного по вашим позициям.** «Раз уж скачал доску,
  посмотрю доходность своего портфеля» — момент, когда вы начинаете смотреть на
  непроверенные числа о собственных деньгах;
* **никакой покупки по несверенной YTM.** Скринер опаснее дашборда: дашборд
  врёт о прошлом, скринер — о будущем, и на нём тратятся деньги;
* **никакой записи в боевую БД.** Хранилище отдельное: `data/bondlab/`, SQLite,
  нулевое пересечение с PostgreSQL основного проекта.

Здесь нет ни одной функции, принимающей портфель на вход, и это не случайность.

## Команды

```bash
export PYTHONPATH=src:scripts

python -m bondlab boards                    # перечень досок: коды меняются, выписывать руками нельзя
python -m bondlab pull TQOB --limit 30      # доска + описание и bondization по каждой бумаге
python -m bondlab schedule SU26238RMFS4     # график платежей из снапшота, глазами
python -m bondlab verify --board TQOB       # свой расчёт против биржевого
```

`boards` и `pull` ходят в сеть. `schedule` и `verify` работают только с диска:
выгрузка и разбор разделены намеренно — ISS отвечает медленно, а перезапускать
разбор вы будете десятки раз.

`verify` возвращает код 1 при наличии выбросов: команда предназначена для cron,
а выброс — повод посмотреть, а не фон.

## Что где лежит

```
data/bondlab/                       (вне git)
  cache/                            дисковый кеш ответов по хешу запроса
  snapshots/{дата}/boards/          перечень досок
  snapshots/{дата}/board-securities/{board}.json
  snapshots/{дата}/securities/{secid}.json
  snapshots/{дата}/bondization/{secid}.json
  bondlab.sqlite                    прогоны verify-yields

tests/fixtures/iss/snapshots/       эталонный набор, та же структура
```

Каталог снапшотов меняется переменной `BONDLAB_DIR`. Тесты и прогон на
фикстурах:

```bash
BONDLAB_DIR=tests/fixtures/iss python -m bondlab verify --board TQCB
```

## Модули

| Файл | Что делает |
|---|---|
| `iss.py` | клиент ISS: `iss.meta=off`, ограничение ~5 запросов в секунду, retry с экспоненциальной паузой, дисковый кеш, пагинация по 100 записей |
| `snapshots.py` | каталог снапшотов: сохранение и чтение. Отсутствие файла — ошибка, а не пустой результат |
| `parse.py` | ответы ISS → `BondSchedule`. Единственная содержательная часть трека |
| `verify.py` | сверка своего расчёта с биржевым, распределение расхождений, выбросы с подсказками |
| `store.py` | SQLite прогонов |
| `cli.py` | команды |

## Как читать результат `verify`

Первая таблица — распределение расхождений по источникам цены. Сравнивать свой
расчёт можно только с тем полем доходности, для которого известна
использованная цена: `PREVWAPRICE` ↔ `YIELDATPREVWAPRICE`, `WAPRICE` ↔
`YIELDATWAPRICE`, `LAST` ↔ `YIELD`. Сравнение своей доходности с биржевой по
другой цене методологически бессмысленно.

Вторая таблица — выбросы с колонкой причин. Куда смотреть, в порядке
вероятности (`PARALLEL-TRACK.md`, B1):

1. база начисления дней (ACT/365, ACT/ACT, 30/360) — параметр `--day-count`;
2. эффективная доходность против номинальной;
3. цена, к которой относится биржевое поле;
4. амортизация не учтена в номинале на дату;
5. оферта — биржа считает к ней, вы к погашению (колонка «к оферте» это
   показывает прямо);
6. купон флоатера не зафиксирован на текущий период;
7. валюта номинала не совпадает с валютой цены.

Почти всегда это конвенция, а не арифметика. Каждая находка — кандидат в
`ASSUMPTIONS.md`.

Отдельно: если НКД не сошёлся ни на одной дате расчётов, дальше сравнивать
доходности незачем — ошибка в графике платежей уже найдена.
